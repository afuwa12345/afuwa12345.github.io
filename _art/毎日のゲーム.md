# 毎日のゲーム — 作る順番と手順

毎日ミニゲームを1本ずつ増やしている。夜中3時のルーティンがこのファイルを読んで作る。
**人がいない時間に動くので、迷ったら足を止めずに、できるところまでやって残りを報告すること。**

---

## 0. `git push` が 403 で断られたときの逃げ道（かならず読む）

**2026-11-27 の回は、ゲームを作りきったのに push が 403 で断られて、コミット2つが
コンテナごと消えた。** サーバーは「Claude にこのリポジトリの GitHub アクセスが無い」と返す。
`git push` を何回やっても同じ。**ここであきらめないこと。**

`git push` が通らなくても、**GitHub の MCP ツールは通る**（読みは実際に通った）。次の順で出しきる:

1. `ToolSearch` で `select:mcp__github__push_files` を読み込む
2. `git diff --name-only origin/cleanup/remove-prediction` で、変えたファイルの一覧を出す
3. `mcp__github__push_files` に渡す
   - owner = `afuwa12345`
   - repo = `afuwa12345.github.io`
   - branch = `cleanup/remove-prediction`
   - message = コミットメッセージと同じ文
4. `mcp__github__get_file_contents` で、ほんとうに入ったか確かめる
5. それでも通らなかったら、**何を作って、どこで止まったかを報告にはっきり書く**。
   人がやることも1行で書く → GitHub App を入れ直す https://github.com/apps/claude/installations/select_target

### アフロくずし（11/28ぶん）は出した

`game/kuzushi.html`。絵は `images/kuzushi/` の切り出しずみをそのまま使ってある。
背景は、元の絵の上に描いてあるブロックと左のアフワを落とした

あとから盤ものを作るときのために、この回で分かったこと:

- **縦長のスマホで盤をたてにいっぱい伸ばすと、玉の1往復が4秒かかって間延びする。**

- **パネルが閉じていると CSS アニメも rAF も止まる。**

  `requestAnimationFrame` / `setTimeout` / `performance.now` を差しかえて早回しする

## 2. 作りの最低ライン（ここを外すと「ちゃっちい」と言われる）

2026-11-26 に、作ったゲーム2本とも「まじでどっちもちゃっちい」と言われた。原因は中身ではなく見た目の作り込み。
**新しいゲームは最初からこの3つを満たすこと。**

1. **キャラのコマを複数枚使う。** 1枚の絵を `@keyframes` で上下させるだけにしない。
   生成シートは2x2なので、1枚で4コマ取れる。動くものは必ず2コマ以上。
2. **世界が動く。** 背景・地面・盤のどれかが必ず動く（スクロール、パララックス、寄り引き）。
   静止画の上で駒だけ動くと、とたんに安く見える。
3. **手ごたえを入れる。** 当たった瞬間に、画面ゆれ・フラッシュ・粒・ヒットストップ（60〜90ms止める）・
   スカッシュ＆ストレッチ・イージングのうち最低3つ。音も動きと同じ瞬間に鳴らす。

**相手（CPU）がいるゲームは、必ず強さを実測してから出す。** アフロオセロで、ふつうに先読みさせたら
てきとうに打つ側の勝率が0%になった（400局で確認）。誰も勝てないゲームは二度と開かれない。
目安は「適当に打つ人で勝率2〜3割、考えて打つ人で8割」。
先読みを浅くする・何回かに1回わざと気まぐれに打つ、で調整する。

**さらに、相手がいるゲームには必ずこの2つを付ける**（アフロオセロ 11/27 で入れた形。
五目ならべ・四目ならべなど、これから作る盤ものも同じにすること）:

1. **強さを10段から選ばせる。** 1段ずつ実測して、名前と一行説明を付ける。
   選んだ段は `localStorage` に覚えさせる。はじめの設定は5。
   弱い段（1〜4）は**練習あつかいで、自己ベストにもランキングにも残さない**。
   残すと、弱い相手で取った点が1位になってランキングが意味を失う。
2. **「ふたりで」を付ける。** 1台を交代でまわす人どうしの対戦。
   HUDのラベルを P1 / P2 に差しかえ、どちらの番でも人が置くようにするだけで作れる。
   こっちも記録はつけない。結果は `#gResult` に `.gr-card` を自前で組んで出す。

文字の決まり:
- **HUDのラベルはローマ字**（SCORE / TIME / TURN）。`Bebas Neue` に日本語の字が無いので、
  日本語を入れるとOS標準の細い書体に落ちて潰れる。
- 共通CSSの `css/afro-arcade.css` はすでに読みやすさを上げてある。勝手に小さくしない。

## 3. 1本作るときに触る場所（全部やる）

1. `game/<key>.html` … 本体。`game/gate.html` が一番素直な見本
2. `game.html` … カードを1枚足す（`data-game="<key>"`）＋ 下のほうの `UNIT` に点の見せかたを足す
3. `js/afro-sfx.js` … `SONGS` にそのゲームのBGMを1つ足す
4. `images/icon/<key>.webp` … 一覧とタイトル画面の丸バッジ（320x320 webp）
5. ランキングは `AfroScore.setup({ game:'<key>', … })` を書けば繋がる
   （※ Apps Script 側にキーを足すのは人の作業。繋がっていなくてもゲームは出せる）

共通CSS: `css/afro-arcade.css`（`.ascreen` `.astage` `.ahud` `.acue` `.abtn` `.gr-*`）

## 4. 絵の入れかた

絵は Codex（OpenAIのアプリ）で本人が作る。**ルーティンからは絵を作れない。**

**1日の流れ**（2026-11-26 に決めた）:

| 時刻 | 誰 | すること |
|---|---|---|
| 前日 15:00 | 本人 | `_art/<key>/Codex生成指示_<key>.md` を Codex に渡して絵を作る。`_art/ref/AFRO_MASTER.png` を添付 |
| 前日 中 | 本人/Claude | 出てきた PNG を `_art/<key>/sheets/` に置いてコミット・push |
| 当日 03:00 | ルーティン | その絵を使ってゲームを作り、本番へ push |

`_art/<key>/sheets/` に PNG が入っていればそれを使い、無ければ既存素材で作りきる。**絵待ちで止めない。**
（クラウド側はリポジトリの中しか見えない。シートが push されていないと絵は無いのと同じ。）

- 2x2シート → `python _art/tools/split4.py _art/<key>/split_map.json` で4枚に切る
- 切った絵は `images/<key>/` に webp で入れる
- アイコンは生成の時点で題字が入っている。崩れていたら `_art/tools/badge.py` で乗せ直す
- 絵が無いときは、`images/face/*.webp` や `images/battle/*.png` など**サイトにある本物の絵**を使う。
  SVGを手書きした仮アイコンは「ショボい」と言われたので作らない
